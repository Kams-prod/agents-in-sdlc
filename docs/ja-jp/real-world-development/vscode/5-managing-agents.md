GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行するなど、自律的に作業します。この作業はユーザーのコンピューター上でリアルタイムに進むため、VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集を進行中に確認できます。各差分をその場でレビューして個別に変更を採用または破棄し、追加のプロンプトで会話を調整、拡張することもできます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッション中にエージェントへ指示を追加し、ハイコントラストモードと合わせてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードへの切り替えも追加してほしいとのことです。新しい会話を最初から開始するのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行した各手順（調べたファイル、実行したコマンド、提案した編集）が表示されます。各ファイルの編集は差分とともにチャット内に表示され、**Keep** と **Undo** の操作ができます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がその場で表示されます。
    - **Keep** を選択すると変更を採用します。
    - **Undo** を選択すると変更を元に戻し、エージェントにもう一度作業させます。
4. チャットの上部にある **Files changed** を開くと、このセッションでエージェントが変更したファイルの全体を確認できます。

> [!NOTE]
> ツールから権限を求められる場合（たとえば、ターミナルコマンドの実行）、エージェントは一時停止し、**Allow** プロンプトを表示します。実行を許可するコマンドを確認してから承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に変更の概要が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードの実装ができたら、同じ会話を続けてライトモードの切り替えを追加します。前の作業を引き継ぐため、変更したコンポーネント、スタイルのアプローチ、設定を local storage に保存する方法などのコンテキストが保持されます。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を引き継ぎ、既存の変更を確認してからライトモードの追加を提案します。
3. 以前と同じように、新しい編集をレビューします。各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、切り替え UI を意図しない形にリファクタリングする場合）、チャット入力欄の横にある **Stop** ボタンで作業を停止し、具体的な追加メッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すより速く調整できます。追加プロンプトを使って、「CSS を簡潔にして、セレクターを重複させず CSS 変数を使ってください」のように修正を依頼したり、「3 つ目の切り替えは追加せず、既存の設定パネルにライトモードを追加してください」のように方向を調整したり、「両方の切り替えにキーボードショートカットも追加してください」のように作業範囲を広げたりできます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが変更したファイルをまとめて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連するテストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティパターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージングしてコミットします。次の[レッスン][next-lesson]で変更を公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して方向を調整しました。ファイルの編集ごとにレビューし、変更を採用または破棄し、コンテキストを失わずに追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を採用または破棄する
- 作業中のセッションに追加プロンプトを送って方向を調整する

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このハンズオンを通じてローカルのカスタムエージェントが作成した変更をレビューします。
